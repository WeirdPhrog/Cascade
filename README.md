# Cascade

Промежуточный IPv4-сервер для TCP/UDP: **клиент → ваш VPS → конечный VPN/прокси**.
Меню на русском, команды `cascade` и `gokaskad`. Подходит для WireGuard/AmneziaWG (UDP),
VLESS/XRay и MTProto (TCP), а также перенаправления между разными портами.

Это NAT relay. Он не устанавливает VPN-сервер, не создаёт ключи и не добавляет шифрование.
Параметры VPN, UUID, ключи, TLS/SNI и проверка сертификатов остаются от конечного сервера.
Пункт TProxy в старом скрипте был обычным TCP DNAT, настоящего transparent proxy там не было.

## Установка

Поддерживаются **Debian 12/13 и Ubuntu 22.04/24.04**, systemd, root и обычное Linux-ядро
с nftables/conntrack. OpenVZ и непривилегированные контейнеры могут не иметь необходимых прав.

```bash
wget -O install.sh https://raw.githubusercontent.com/WeirdPhrog/Cascade/main/install.sh
sudo bash install.sh
```

Для автоматизации: `sudo bash install.sh --no-menu`. Для воспроизводимой установки замените
`main` на конкретный проверенный commit SHA и скачайте рядом `cascade.py` из **того же коммита**.
Или клонируйте репозиторий и запустите установщик из клона. Локальный `cascade.py` проверяется
по SHA-256 так же, как скачанный. Если main обновился между скачиваниями, несовпадение хеша
останавливает установку: скачайте оба файла одной версии.

Установщик получает из apt пакеты `python3`, `nftables`, `conntrack`, `iproute2`,
`ca-certificates`, `curl` и их системные зависимости. Исходные системные пакеты поставляет
ваш Debian/Ubuntu; их копии в репозиторий не включены. Gist и сторонние скрипты не исполняются.

## Настройка

```bash
sudo cascade
# Совместимое имя команды:
sudo gokaskad

# Адрес назначения и порт VPN; локальный IP определяется по маршруту к цели:
sudo cascade add --proto udp --in-port 51820 --target 203.0.113.10 --out-port 51820

# Явный локальный адрес и разные порты:
sudo cascade add --proto tcp --listen 192.0.2.10 --in-port 8443 \
  --target 203.0.113.10 --out-port 443

sudo cascade list
sudo cascade status
```

**Замените адреса из примеров своими.** `--listen` — адрес, назначенный интерфейсу VPS.
Если провайдер использует внешний NAT, это может быть внутренний IP, а клиент использует
публичный IP VPS. Входящий порт также нужно открыть в firewall/security group провайдера.
Не указывайте `0.0.0.0`: явная привязка нужна для безопасного удаления conntrack и чтобы
не перехватывать пакеты, предназначенные другим адресам.

В VPN-клиенте поменяйте только адрес подключения и порт на публичный IP промежуточного VPS
и входящий порт правила. Для проверки используйте **другую машину**: локально созданные
соединения VPS не проходят через PREROUTING и не перенаправляются.

Повторное добавление идентичного правила безопасно. Чтобы изменить цель существующего
входа, используйте `--replace`. Входящий TCP-порт, занятый SSH или другим локальным сервисом,
по умолчанию запрещён. `--allow-local-port` явно разрешает его перехват и может оборвать доступ
к сервису; обычно выбирайте свободный порт.

## Удаление

```bash
sudo cascade delete --proto udp --listen 192.0.2.10 --in-port 51820
sudo cascade clear --yes             # только правила Cascade
sudo bash install.sh --uninstall     # правила, программа и systemd unit
```

Удаление убирает DNAT/MASQUERADE и очищает conntrack только по удалённым входящим
адресу/порту, протоколу и адресу/порту цели. Другие правила, таблицы и системные пакеты
остаются. Повторное удаление отсутствующего правила или уже удалённой программы допустимо.
При ошибке conntrack команда сообщает, что правила удалены, но старые соединения могли остаться.
Их можно найти командой `sudo conntrack -L` и удалить по тому же полному набору полей.

## Состояние и firewall

* Настройки: `/etc/cascade/state.json`, права 0600, каталог 0700.
* Программа: `/usr/local/lib/cascade/cascade.py`; два symlink в `/usr/local/bin`.
* Только собственная таблица `ip cascade_v1`; её замена — одна транзакция nftables.
* `cascade.service` восстанавливает правила и forwarding после загрузки сети.
  `sudo systemctl reload cascade` повторно применяет сохранённые правила.
* `sudo cascade stop` временно убирает правила; `sudo cascade apply` возвращает их.
* Исходное `net.ipv4.ip_forward` сохраняется перед первым правилом и возвращается после
  последнего удаления/остановки. `sysctl.conf`, BBR, UFW и политики INPUT/FORWARD не редактируются.
* Для параллельных команд используется файловая блокировка. Ошибка применения/записи
  состояния запускает откат предыдущих правил и forwarding.

**Предполагается выделенный промежуточный VPS.** `ip_forward` — общая настройка ядра.
Если после первого правила другое ПО тоже начало использовать маршрутизацию, согласуйте
значение `previous_forward` в состоянии перед остановкой Cascade; восстановление исходного `0`
отключит маршрутизацию и для этого ПО. Не редактируйте state.json при работающих командах.

Cascade не обходит UFW, Docker или другие firewall. Если найдена сторонняя цепочка FORWARD,
добавление останавливается. Настройте в своём firewall разрешения пересылки к конечному адресу
и порту, включая ответы, затем укажите `--external-firewall` при добавлении. Это согласие
сохраняется для последующих загрузок. **Флаг не добавляет разрешения**: drop в чужой цепочке
по-прежнему блокирует трафик. Счётчики `cascade status` и проверка с клиента помогают диагностике.

Не сохраняйте таблицу Cascade дополнительно через `nft list ruleset > /etc/nftables.conf`:
её жизненным циклом управляет `cascade.service`. После перезагрузки стороннего firewall,
который выполняет глобальный flush, может понадобиться `systemctl reload cascade`.

IPv6, диапазоны портов, DNS-имена целей, балансировка и настройка VPN-сервера не поддерживаются.
Частные IPv4 назначения разрешены для работы через приватную сеть.

проверку Bash/ShellCheck, установку и удаление с настоящим systemd на Ubuntu 22.04/24.04
и в контейнерах Debian 12/13, а также TCP/UDP-тесты в трёх Linux network namespaces. Подробности:
[аудит](docs/AUDIT.md), [миграция со старого скрипта](docs/MIGRATION.md),
[происхождение исходника](upstream/README.md).

```bash
python3 -m unittest discover -s tests -v
python3 tests/check_integrity.py
# Только Linux с root; создаёт и удаляет собственные временные network namespaces:
sudo python3 tests/integration.py
```
