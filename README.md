# Cascade

Промежуточный IPv4-сервер для TCP/UDP: **клиент → ваш VPS → конечный VPN/прокси**.
Меню на русском, команда `cascade`. Подходит для WireGuard/AmneziaWG (UDP),
VLESS/XRay и MTProto (TCP), а также перенаправления между разными портами.

Это NAT relay. Он не устанавливает VPN-сервер, не создаёт ключи и не добавляет шифрование.
Параметры VPN, UUID, ключи, TLS/SNI и проверка сертификатов остаются от конечного сервера.
Все правила перенаправления создаются и удаляются через **iptables**.

## Установка

Поддерживаются **Debian 12/13 и Ubuntu 22.04/24.04**, systemd, root и обычное Linux-ядро
с iptables/conntrack. Используется уже выбранный в системе вариант iptables,
без переключения системных настроек. OpenVZ и непривилегированные контейнеры
могут не иметь необходимых прав.

```bash
wget -O install.sh https://raw.githubusercontent.com/WeirdPhrog/Cascade/main/install.sh && sudo bash install.sh
```

Для автоматизации: `sudo bash install.sh --no-menu`. Для воспроизводимой установки замените
`main` на конкретный проверенный commit SHA и скачайте рядом `cascade.py` из **того же коммита**.
Или клонируйте репозиторий и запустите установщик из клона. Локальный `cascade.py` проверяется
по SHA-256 так же, как скачанный. Если main обновился между скачиваниями, несовпадение хеша
останавливает установку: скачайте оба файла одной версии.

Системные зависимости устанавливаются через apt: `python3`, `iptables`, `nftables`,
`conntrack`, `iproute2`, `ca-certificates`, `curl`. Пакет `nftables` нужен только для
чтения существующих правил и проверки конфликтов с другими firewall.

## Настройка

После первой установки перенаправлений ещё нет: создайте правило через меню или команду
ниже. Конечный VPN/прокси должен быть уже настроен и доступен с промежуточного VPS.

```bash
sudo cascade

# Адрес назначения и порт VPN; локальный IP определяется по маршруту к цели:
sudo cascade add --proto udp --in-port 51820 --target 203.0.113.10 --out-port 51820

# Явный локальный адрес и разные порты:
sudo cascade add --proto tcp --listen 192.0.2.10 --in-port 8443 \
  --target 203.0.113.10 --out-port 443

sudo cascade list
sudo cascade status
```

**Замените адреса из примеров своими.** `--listen` — адрес, назначенный интерфейсу VPS.
Если провайдер использует внешний NAT, это может быть внутренний IP, а клиент использует
публичный IP VPS. Входящий порт также нужно открыть в firewall/security group провайдера.
Не указывайте `0.0.0.0`: явная привязка нужна для безопасного удаления conntrack и чтобы
не перехватывать пакеты, предназначенные другим адресам.

В VPN-клиенте поменяйте только адрес подключения и порт на публичный IP промежуточного VPS
и входящий порт правила. Для проверки используйте **другую машину**: локально созданные
соединения VPS не проходят через PREROUTING и не перенаправляются.

Повторное добавление идентичного правила безопасно. Чтобы изменить цель существующего
входа, используйте `--replace`. Проверка свободного входящего порта обязательна, в том числе
при замене. В меню занятый порт отклоняется сразу, до создания правила.

Проверяются TCP/UDP-сокеты, чужие DNAT/REDIRECT (включая диапазоны), опубликованные порты
Docker и резервации остановленных контейнеров. Учитываются протокол и локальный адрес:
TCP и UDP с одинаковым номером — разные порты. Проверка Docker работает и без `docker-proxy`.
Если локальный Docker socket есть, но получить список контейнеров не удалось, добавление
останавливается. Флага для принудительного захвата занятого порта нет.

Также запрещены порт 0, неверные IP/порты, локальная цель, loopback, multicast и адрес,
не назначенный VPS. Для цели требуется маршрут типа unicast; local/broadcast/blackhole
не допускаются. Наличие маршрута не подтверждает работоспособность самого VPN.
Эти проверки повторяются непосредственно перед применением правил.

## Удаление

```bash
sudo cascade delete --proto udp --listen 192.0.2.10 --in-port 51820
sudo cascade clear --yes             # только правила Cascade
sudo bash install.sh --uninstall     # правила, программа и systemd unit
```

Удаление убирает DNAT/MASQUERADE и очищает conntrack только по удалённым входящим
адресу/порту, протоколу и адресу/порту цели. Чужие правила и цепочки сохраняются.
Повторное удаление отсутствующего правила или уже удалённой программы допустимо.
При ошибке очистки conntrack операция завершается с ошибкой и восстанавливает прежние
правила. Конфигурация сохраняется для повторной попытки: устраните причину ошибки и
повторите удаление. Уже завершённые соединения при откате не восстанавливаются.

При успешном `--uninstall` удаляются собственные цепочки и переходы Cascade, программа,
команда `cascade`, конфигурация `state.json` и unit `cascade.service`.
Сервис останавливается и отключается от автозапуска.

**Удаление не возвращает ОС к состоянию до установки.** В системе остаются:

* `/etc/cascade/.lock` и его каталог — блокировка команд из ранее открытых меню;
* `/run/lock/cascade-install.lock` — файл блокировки установщика в `/run`;
* установленные через apt зависимости: ими могут пользоваться другие сервисы;
* включённый `net.ipv4.ip_forward`, если Cascade включил его при добавлении правила;
* скачанный `install.sh` (или клон репозитория), системный журнал и журналы apt.

Оставшиеся файлы блокировки не запускают процессов и не создают сетевых правил.

## Состояние и firewall

* Настройки: `/etc/cascade/state.json`, права 0600, каталог 0700.
* Программа: `/usr/local/lib/cascade/cascade.py`; команда `/usr/local/bin/cascade`.
* Свои цепочки: `nat/CSCD_DNAT`, `nat/CSCD_SNAT`, `filter/CSCD_FWD`.
  Правила и переходы помечены комментарием `cascade:v2`; чужие цепочки не очищаются.
* `cascade.service` восстанавливает правила и forwarding после загрузки сети.
  `sudo systemctl reload cascade` повторно применяет сохранённые правила.
* `sudo cascade stop` временно убирает правила; `sudo cascade apply` возвращает их.
* При первом правиле включается `net.ipv4.ip_forward`. После удаления он **остаётся включённым**:
  выключение общей маршрутизации нарушило бы работу Docker/Amnezia. `sysctl.conf`, BBR,
  конфигурация UFW и политики INPUT/FORWARD не редактируются.
* Для параллельных команд используется файловая блокировка. Ошибка применения/записи
  состояния запускает откат собственных правил. Перед применением выполняется
  `iptables-restore --test`; `--noflush` сохраняет чужие цепочки.
* Удаление программы блокирует команды из ранее открытых меню. Повторная установка
  снова разрешает работу. Чужие файлы в путях установки не перезаписываются и не удаляются.

## Docker и Amnezia на том же VPS

Cascade может работать рядом с обычным Docker, использующим iptables, и Amnezia в его
контейнерах. Выбирайте свободный входящий порт. Правила внутри VPN-контейнеров не меняются,
публикации Docker сохраняются. Проверены настоящий Docker без userland proxy, TCP/UDP,
политика `FORWARD DROP` и перезапуск Docker без повторного применения Cascade.

Переходы в `CSCD_FWD` добавляются в начало `FORWARD` и, если она существует, `DOCKER-USER`.
Разрешаются только соединения выбранного перенаправления, ответы и связанные ICMP-ошибки: проверяются
исходный адрес/порт назначения и адрес/порт конечного сервера через conntrack. Поэтому
`FORWARD DROP` не мешает каскаду, а остальной трафик продолжает проходить по прежним правилам.
Эти точечные разрешения имеют приоритет над более поздними фильтрами FORWARD, включая UFW.
Фильтры raw/mangle и firewall провайдера по-прежнему могут блокировать трафик.

Поддерживаются оба системных варианта iptables: `iptables-legacy` и `iptables-nft`.
Второй использует механизм nftables в ядре, сохраняя команды и формат правил iptables.
Это совместимо с Cascade. Но одновременные активные правила в обоих вариантах,
отдельный firewall с собственными правилами nftables на пути пересылки или Docker,
настроенный напрямую на nftables, требуют ручной настройки. При их обнаружении Cascade
отказывается добавлять правила; удаление своих правил остаётся доступным.
Совместимость с произвольной конфигурацией firewall не гарантируется.

Не сохраняйте правила Cascade дополнительно через `netfilter-persistent save` или общий
снимок firewall: ими управляет `cascade.service`. Если сторонняя программа полностью
сбросила firewall, выполните `sudo systemctl reload cascade`.

Проверка занятости отражает состояние на момент добавления/загрузки; она не резервирует
порт в ОС и не мешает другому администратору позднее опубликовать его через Docker.
Не используйте уже выделенный Cascade порт для нового сервиса.

IPv6, диапазоны портов, DNS-имена целей, балансировка и настройка VPN-сервера не поддерживаются.
Частные IPv4 назначения разрешены для работы через приватную сеть.

## Тестирование

[CI](https://github.com/WeirdPhrog/Cascade/actions/workflows/test.yml) выполняет модульные тесты,
проверку Bash/ShellCheck, установку и удаление с настоящим systemd на Ubuntu 22.04/24.04
и в контейнерах Debian 12/13, TCP/UDP-тесты в трёх Linux network namespaces, оба backend
iptables на Ubuntu и отдельный тест с настоящим Docker и правилами по образцу AmneziaWG.
Контейнеры Debian используют ядро Ubuntu-хоста. VPN-рукопожатие самой Amnezia,
реальная перезагрузка VPS и firewall провайдера этими тестами не проверяются.
Дополнительно проверяются параллельные команды, сохранность правил при ошибках NAT,
записи конфигурации и conntrack, повреждённая конфигурация и откат неудачной установки.

```bash
python3 -m unittest discover -s tests -v
python3 tests/check_integrity.py
# Только Linux с root; создаёт и удаляет собственные временные network namespaces:
sudo python3 tests/integration.py
```
