# Аудит и проверка

Дата: 2026-09-22. Объект: точная ревизия gist, указанная в `upstream/README.md`,
и новая реализация из этого репозитория. Это ревизия исходного кода и функциональные тесты,
а не гарантия отсутствия любых уязвимостей ядра, дистрибутива или VPN-сервера.

## Найдено в исходнике

| Приоритет | Проблема | Исправление |
| --- | --- | --- |
| Критический | `flush_rules` меняет политики на ACCEPT и очищает nat/mangle/filter целиком, включая правила других сервисов | Удаление только собственной таблицы `ip cascade_v1` |
| Высокий | UFW переводится на глобальный `DEFAULT_FORWARD_POLICY=ACCEPT` | UFW не меняется; сторонние FORWARD-цепочки требуют настройки владельцем |
| Высокий | Глобальный MASQUERADE для всего интерфейса влияет на чужие соединения и остаётся после удаления | MASQUERADE ограничен DNAT, исходным входящим IP/портом и конечным IP/портом/протоколом |
| Высокий | Команды iptables/apt/sysctl могут завершиться ошибкой, а интерфейс сообщает SUCCESS | Проверка кодов возврата, атомарная транзакция nftables, откат при ошибках |
| Высокий | DNAT применяется ко всем пакетам с данным портом, включая транзитные; можно перехватить SSH | Явный локальный IP, проверка локальных слушающих портов |
| Высокий | Нет надёжного различения собственных и чужих DNAT при просмотре/удалении | Состояние Cascade отдельно; чужие таблицы не перечисляются как свои |
| Средний | «Удаление старого правила» использует новую цель, поэтому прежний DNAT остаётся при смене IP/порта | Уникальный ключ protocol/listen/in-port, явный `--replace` |
| Средний | IP почти не проверяется, допускается порт 0; нет контроля повторов | `ipaddress.IPv4Address`, диапазон 1–65535, схема JSON и уникальность ключей |
| Средний | Неконтролируемый ввод используется как индекс Bash-массива при удалении | Нет арифметической индексации пользовательского ввода |
| Средний | Пакеты после удаления могут продолжить идти по существующей записи conntrack | Адресная очистка conntrack по полному набору полей удалённого правила |
| Средний | Дубли правил, одновременные меню и частично применённые правила | Файловая блокировка, единая транзакция для таблицы |
| Средний | Фиксированное пятое поле `ip route get 8.8.8.8` ненадёжно определяет интерфейс | JSON `ip route get` к реальной цели; masquerade выбирает исходящий интерфейс ядром |
| Средний | При каждом запуске меню меняются sysctl, BBR и сохраняется общий firewall | Просмотр не меняет настройки; BBR не навязывается, общие firewall-снимки не записываются |
| Средний | Нет полноценного удаления программы и восстановления forwarding | `--uninstall`, удаление своих файлов/правил и восстановление сохранённого значения |

В исходнике не обнаружено дополнительных загрузчиков, отправки данных третьим лицам или
скрытых внешних сервисов. Его собственные файлы и зависимости перечислены в provenance.
Глобальный INPUT ACCEPT на входящий порт был лишним: DNAT-пакет к удалённому серверу проходит FORWARD.

## Проверяемые свойства

* Модульные тесты: входные значения, коллизия имени таблицы, конфликт с чужим firewall,
  точность NAT, ошибка ядра/записи файла, откат, исходный forwarding и ошибка conntrack.
* Linux network namespaces: отдельные клиент, relay и конечный сервер, реальные TCP/UDP
  echo-соединения, разные входящий/исходящий порты, SNAT при отсутствии обратного маршрута,
  общая цель у нескольких правил, замена, повторное добавление, stop/apply, удаление и clear.
* Чужая sentinel-таблица проверяется до и после очистки; чужой FORWARD DROP не переписывается.
* На Ubuntu 22.04/24.04 проверяются установка/reinstall, работа systemd unit, reload/restart,
  удаление и повторное удаление. SHA-256 bootstrap и неизменность архивного исходника проверяются в CI.

Актуальные результаты запуска и commit SHA доступны в
[GitHub Actions](https://github.com/WeirdPhrog/Cascade/actions/workflows/test.yml).
Windows-окружение разработки выполняет модульные тесты; сетевые проверки выполняются только на Linux.

## Ограничения и остаточные риски

* Проверяется пересылка TCP/UDP, но не рукопожатие каждого конкретного VPN-протокола.
* Проверка stop/apply моделирует восстановление правил, а systemd restart проверяет unit;
  это не физическая перезагрузка вашего VPS.
* `--external-firewall` подтверждает наличие самостоятельно настроенных FORWARD-разрешений.
  ACCEPT одного firewall не отменяет DROP другого. Внешние security groups CI не проверяет.
* nftables-транзакция атомарна, а JSON и ядро не образуют общей транзакции. При аварийном
  отключении питания между применением и сохранением после reboot будет восстановлена
  последняя сохранённая конфигурация. При обычных исключениях выполняется откат.
* Forwarding — глобальная настройка; предполагается выделенный relay. Другому ПО может
  понадобиться оставить forwarding включённым при удалении Cascade; см. README.
* Root может менять таблицу/состояние/программу вручную. Защита от враждебного root не заявляется.
* SHA-256 проверяет соответствие скачанного компонента установщику, но не является подписью
  автора. Для воспроизводимости используйте проверенный commit; доверие к GitHub/HTTPS остаётся.
* В IPv4 conntrack уже установленные TCP-сессии после принудительного удаления связи
  обрываются; замена цели требует нового VPN-подключения.

Техническая основа: [nftables manual](https://netfilter.org/projects/nftables/manpage.html),
[NAT в nftables](https://wiki.nftables.org/wiki-nftables/index.php/Performing_Network_Address_Translation_%28NAT%29).
