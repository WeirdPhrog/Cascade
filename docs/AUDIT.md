# Аудит и проверка

Дата: 2026-09-22. Объект: точная ревизия gist, указанная в `upstream/README.md`,
и новая реализация из этого репозитория. Это ревизия исходного кода и функциональные тесты,
а не гарантия отсутствия любых уязвимостей ядра, дистрибутива или VPN-сервера.

## Найдено в исходнике

| Приоритет | Проблема | Исправление |
| --- | --- | --- |
| Критический | `flush_rules` меняет политики на ACCEPT и очищает nat/mangle/filter целиком, включая правила других сервисов | Удаление только помеченных цепочек CSCD_* и переходов Cascade |
| Высокий | UFW переводится на глобальный `DEFAULT_FORWARD_POLICY=ACCEPT` | Политики и конфигурация UFW сохраняются; разрешены только соединения Cascade |
| Высокий | Глобальный MASQUERADE для всего интерфейса влияет на чужие соединения и остаётся после удаления | MASQUERADE ограничен DNAT, исходным входящим IP/портом и конечным IP/портом/протоколом |
| Высокий | Команды iptables/apt/sysctl могут завершиться ошибкой, а интерфейс сообщает SUCCESS | Проверка кодов возврата, iptables-restore --test/--noflush, откат своих правил при ошибках |
| Высокий | DNAT применяется ко всем пакетам с данным портом, включая транзитные; можно перехватить SSH | Явный локальный IP, обязательная проверка сокетов, Docker и чужого DNAT/REDIRECT |
| Высокий | Нет надёжного различения собственных и чужих DNAT при просмотре/удалении | Состояние Cascade отдельно; чужие таблицы не перечисляются как свои |
| Средний | «Удаление старого правила» использует новую цель, поэтому прежний DNAT остаётся при смене IP/порта | Уникальный ключ protocol/listen/in-port, явный `--replace` |
| Средний | IP почти не проверяется, допускается порт 0; нет контроля повторов | `ipaddress.IPv4Address`, диапазон 1–65535, схема JSON и уникальность ключей |
| Средний | Неконтролируемый ввод используется как индекс Bash-массива при удалении | Нет арифметической индексации пользовательского ввода |
| Средний | Пакеты после удаления могут продолжить идти по существующей записи conntrack | Адресная очистка conntrack по полному набору полей удалённого правила |
| Средний | Дубли правил, одновременные меню и частично применённые правила | Файловая блокировка, restore с ожиданием xtables lock, откат при обычных ошибках |
| Средний | Фиксированное пятое поле `ip route get 8.8.8.8` ненадёжно определяет интерфейс | JSON `ip route get` к реальной цели; masquerade выбирает исходящий интерфейс ядром |
| Средний | При каждом запуске меню меняются sysctl, BBR и сохраняется общий firewall | Просмотр не меняет настройки; BBR не навязывается, общие firewall-снимки не записываются |
| Средний | Нет полноценного удаления программы | `--uninstall`, удаление своих файлов/правил; общая маршрутизация сохраняется для других сервисов |

В исходнике не обнаружено дополнительных загрузчиков, отправки данных третьим лицам или
скрытых внешних сервисов. Его собственные файлы и зависимости перечислены в provenance.
Глобальный INPUT ACCEPT на входящий порт был лишним: DNAT-пакет к удалённому серверу проходит FORWARD.

## Проверяемые свойства

* Модульные тесты: входные значения, коллизии цепочек и чужие ссылки, занятые порты,
  точность NAT, ошибка ядра/записи файла, откат, сохранение forwarding и ошибка conntrack.
* Linux network namespaces: отдельные клиент, relay и конечный сервер, реальные TCP/UDP
  echo-соединения, разные входящий/исходящий порты, SNAT при отсутствии обратного маршрута,
  общая цель у нескольких правил, замена, повторное добавление, stop/apply, удаление и clear,
  связанные ICMP-ошибки при FORWARD DROP, переход с непустого состояния v1 на iptables.
  На Ubuntu — backend nft и legacy.
* Чужая sentinel-таблица проверяется до и после очистки; чужой FORWARD DROP не переписывается.
* На Ubuntu 22.04/24.04 и в контейнерах Debian 12/13 проверяются установка/reinstall,
  работа systemd unit с сохранёнными правилами, reload/restart/stop/start, удаление и повторное
  удаление. Debian-контейнеры используют ядро хостовой Ubuntu, поэтому отдельное ядро Debian
  этими тестами не проверяется. SHA-256 bootstrap и неизменность архивного исходника проверяются в CI.
* Отдельная одноразовая VM запускает настоящий Docker без userland proxy и контейнер
  с FORWARD/MASQUERADE-правилами по образцу AmneziaWG. Проверяются TCP/UDP-публикации,
  занятые порты запущенного и остановленного контейнера, одновременный трафик Docker/Cascade,
  перезапуск Docker и сохранность чужих правил после clear. Счётчики пакетов при сравнении
  исключаются; таблицы, цепочки, политики, правила и их порядок должны совпасть.

Актуальные результаты запуска и commit SHA доступны в
[GitHub Actions](https://github.com/WeirdPhrog/Cascade/actions/workflows/test.yml).
Windows-окружение разработки выполняет модульные тесты; сетевые проверки выполняются только на Linux.

## Ограничения и остаточные риски

* Проверяется пересылка TCP/UDP, но не рукопожатие каждого конкретного VPN-протокола.
* Проверка stop/apply моделирует восстановление правил, а systemd restart проверяет unit с непустой конфигурацией;
  это не физическая перезагрузка вашего VPS.
* Разрешения Cascade стоят перед прочими фильтрами FORWARD, но ограничены конкретным
  перенаправлением. Raw/mangle, независимый nftables firewall и внешние security groups
  могут блокировать трафик; неизвестный native nftables firewall на пути пересылки
  и смешанные backend отклоняются. Стандартные цепочки iptables-nft распознаются по
  семейству, таблице, имени, hook, типу и приоритету; это не защита от подмены root.
* Таблицы nat/filter и JSON не образуют общей транзакции. При обычных исключениях
  выполняется откат собственных правил, без восстановления общего firewall-снимка.
  При аварийном завершении между операциями может потребоваться `cascade apply`;
  после загрузки systemd восстанавливает последнюю сохранённую конфигурацию.
* Forwarding — общая настройка: включается при необходимости, но при удалении/откате
  не выключается. Чужие процессы могут менять firewall одновременно; xtables lock
  защищает одну операцию restore, а не весь жизненный цикл Docker и Cascade.
* Проверка свободного порта не является его резервированием. Последующие публикации
  Docker/локальные сервисы нужно создавать на других портах. Необычные DNAT-правила
  проверяются консервативно и могут потребовать выбрать другой входящий порт.
* Root может менять таблицу/состояние/программу вручную. Защита от враждебного root не заявляется.
* SHA-256 проверяет соответствие скачанного компонента установщику, но не является подписью
  автора. Для воспроизводимости используйте проверенный commit; доверие к GitHub/HTTPS остаётся.
* В IPv4 conntrack уже установленные TCP-сессии после принудительного удаления связи
  обрываются; замена цели требует нового VPN-подключения.

[conntrack match](https://man7.org/linux/man-pages/man8/iptables-extensions.8.html),
[Docker и iptables](https://docs.docker.com/engine/network/firewall-iptables/),
[правила AmneziaWG](https://github.com/amnezia-vpn/amnezia-client/blob/dev/client/server_scripts/awg_legacy/start.sh).
