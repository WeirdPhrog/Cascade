# Миграция с исходного gokaskad

Для новой машины достаточно `install.sh`. Старые правила автоматически не импортируются
и не удаляются: исходник не помечал владельца правил, поэтому отличить их от чужих надёжно нельзя.
Установщик останавливается, если `/usr/local/bin/gokaskad` — старый файл вместо нашего symlink.

1. Через отдельную SSH-сессию/консоль провайдера сохраните `iptables-save`, `ip6tables-save`,
   `/etc/iptables/rules.v4`, `/etc/iptables/rules.v6`, `/etc/sysctl.conf` и `/etc/default/ufw`,
   если эти файлы существуют. Запишите старые протоколы, входящие порты и цели.
2. Удалите каждое нужное перенаправление **по точной спецификации**, сверив с
   `sudo iptables-save`. Не используйте пункт «Сбросить ВСЕ настройки» старого меню.
   Старые правила не имеют меток, а его список показывает и чужие DNAT.
3. Проверьте оставшийся `POSTROUTING -o ИНТЕРФЕЙС -j MASQUERADE`: старое удаление
   его не убирает. Удаляйте только если уверены, что правило было создано старым скриптом
   и не используется другим VPN/Docker/маршрутизатором.
4. Аналогично проверьте открытые INPUT-порты, FORWARD-разрешения, UFW и BBR/sysctl.
   Старый скрипт не сохранял предыдущие значения, поэтому автоматическое восстановление
   исходной конфигурации невозможно.
5. Если используется netfilter-persistent, после ручной проверки сохраните исправленные
   правила через `sudo netfilter-persistent save`, чтобы старые правила не вернулись после reboot.
6. Переместите старый `/usr/local/bin/gokaskad` в резервную копию вне этого пути.
   Установите Cascade и создайте записанные правила заново, задав локальный адрес VPS.
7. Проверьте соединение с клиента, затем `systemctl reload cascade` и повторите проверку.
   Перезагрузку реального VPS выполняйте с доступной консолью провайдера.

Не запускайте одновременно старое меню и новое: `netfilter-persistent save` сохраняет общий
firewall, а старый global flush способен уничтожить правила посторонних приложений.
